# Clawd 快跑 · 地图设计 v0.8.0

## 目标与边界

- 继续使用 400×225 固定视角横版画布、自动跑、跳跃、滑铲和达里奥追逐机制。
- 优先提供 **房间结构的辨识度和操作节奏**，而不是堆高障碍密度。
- 当前所有美术由 Canvas 绘制，保存为插件内源代码，不依赖网络图片或新增构建工具。
- 地图装饰全部在背景层，无碰撞；地面障碍依然只有 `low` 与 `high` 两类。

## 空间构成

每 300m 切换一次大区域：服务器区（sector 0）→ 冷却区（sector 1）→ 核心区（sector 2）→ 循环。

每个区域固定为四段 75m：

| 段落 | 主要体验 | 障碍变化 |
| --- | --- | --- |
| 0 通道 | 调整状态、识别新区域 | 单障碍为主，适度双障碍 |
| 1 设备区 | 建立地图特色 | 按区域权重产生低/高障碍 |
| 2 挑战区 | 组合操作 | 中高难度后可出现三连 |
| 3 气闸出口 | 场景交接与缓冲 | **只出单障碍**，下一组冷却时间延长 |

重复循环后的设备/挑战场景命名顺序交替，但**总区长度不变**，不会改变原有分数与存档距离语义。

## 三个区域的玩法与视觉关键词

- **服务器区**：服务器机箱为主要障碍；墙面安全扫描控制台、机架、设备警示灯。黄色机箱警示色。
- **冷却区**：激光门和滑铲偏多；冷却储液罐、上浮气泡、地面格栅与冷光。障碍机箱使用冷蓝警示色。
- **核心区**：跳跃和滑铲交替；呼吸光密封舱、导管、红色警报灯。障碍机箱使用暖红橙警示色。

**可读性原则**：红色水平激光线只用于可碰撞障碍；大型装饰必须留在角色后方。所有碰撞盒维持原规格。

## 区域过渡

- `sectorBlendOf(distance)`：距离区域边界 ±24m 时计算平滑 alpha 混合，绘制旧/新两层墙面与专属地面。
- `drawMapAirlock`：按照世界坐标固定在每个 300m 区域边界，不会突然闪现；角色可直接穿过。
- `drawMapSetpieces`：以世界坐标每 460px 摆放一次场景物件，和背景的慢速视差层区分开。
- `drawMapFloorMarkers`：每 75m 标注一个细小地面段落标记，不参与游戏逻辑。

## 修改位置

- `lib/client.js` 中 `#region game-core`：`mapSegmentOf`、`sectorBlendOf`、`createObstaclePattern`、`stepGame`、存档/恢复。
- 同文件渲染段：`drawMapSecurityBay`、`drawMapCoolantTank`、`drawMapContainment`、`drawMapAirlock`、`drawMapSetpieces`、`drawFloorSectorDetail`、`drawBackground`。
- `test/game.test.mjs`：加入地图与存档兼容测试；旧物理和碰撞回归测试保留。

## 实机验收

建议在 DSH 中分别检验距离 0m、270–330m、570–630m、870–930m：

1. 墙面与地面是否柔和过渡，气闸门是否随画面移动而不是突然出现。
2. 安全控制台、储液罐和核心密封舱能否一眼区分，并且不遮挡 Clawd、真正的激光门和 token。
3. 长跑时三区的操作节奏是否明显不同；出口段是否有喘息时间。
4. 运行中按 P 暂停后继续，三连障碍是否保持原有间距。
5. 加载 `dshclawd.game.v1` 的旧存档是否保持可玩。
