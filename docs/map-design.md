# Clawd 快跑 · 地图设计 v0.8.1

## 目标与边界

- 继续使用 400×225 固定视角横版画布、自动跑、跳跃、滑铲和达里奥追逐机制。
- 优先提供 **房间结构的辨识度和操作节奏**，而不是堆高障碍密度。
- 背景美术由 Canvas 和原创 SVG 图集共同绘制，图集内嵌到客户端以支持离线显示。
- 地图装饰全部在背景层，无碰撞；地面障碍依然只有 `low` 与 `high` 两类。

## 空间构成

每 300m 切换一次大区域：服务器区（sector 0）→ 冷却区（sector 1）→ 核心区（sector 2）→ 循环。

每个区域固定为四段 75m：

| 段落 | 主要体验 | 障碍变化 |
| --- | --- | --- |
| 0 通道 | 调整状态、识别新区域 | 单障碍为主，适度双障碍 |
| 1 设备区 | 建立地图特色 | 按区域权重产生低/高障碍 |
| 2 挑战区 | 组合操作 | 中高难度后可出现三连 |
| 3 气闸出口 | 场景交接与缓冲 | **只出单障碍**，下一组冷却时间延长 |

重复循环后的设备/挑战场景命名顺序交替，但**总区长度不变**，不会改变原有分数与存档距离语义。

## 三个区域的玩法与视觉关键词

- **服务器区**：服务器机箱为主要障碍；墙面安全扫描控制台、机架、设备警示灯。黄色危险机箱。
- **冷却区**：激光门和滑铲偏多；冷却储液罐、上浮气泡、地面格栅与冷光。冷蓝作为背景设备色，危险机箱依然是固定黄橙色。
- **核心区**：跳跃和滑铲交替；呼吸光密封舱、导管、红色警报灯。暖红橙作为背景设备色，危险机箱依然是固定黄橙色。

**可读性原则**：红色水平激光线只用于可碰撞障碍；大型装饰必须留在角色后方。所有碰撞盒维持原规格。

## 区域过渡

- `sectorBlendOf(distance)`：距离区域边界 ±24m 时计算平滑 alpha 混合，绘制旧/新两层墙面与专属地面。
- `drawMapAirlock`：按照世界坐标固定在每个 300m 区域边界，不会突然闪现；角色可直接穿过。
- `drawMapSetpieces`：以世界坐标每 460px 摆放一次场景物件，和背景的慢速视差层区分开。
- `drawMapFloorMarkers`：每 75m 标注一个细小地面段落标记，不参与游戏逻辑。

## 修改位置

- `lib/client.js` 中 `#region game-core`：`mapSegmentOf`、`sectorBlendOf`、`createObstaclePattern`、`stepGame`、存档/恢复。
- 同文件渲染段：`drawMapSecurityBay`、`drawMapCoolantTank`、`drawMapContainment`、`drawMapAirlock`、`drawMapSetpieces`、`drawFloorSectorDetail`、`drawBackground`。
- `test/game.test.mjs`：加入地图与存档兼容测试；旧物理和碰撞回归测试保留。

## 实机验收

建议在 DSH 中分别检验距离 0m、270–330m、570–630m、870–930m：

1. 墙面与地面是否柔和过渡，气闸门是否随画面移动而不是突然出现。
2. 安全控制台、储液罐和核心密封舱能否一眼区分，并且不遮挡 Clawd、真正的激光门和 token。
3. 长跑时三区的操作节奏是否明显不同；出口段是否有喘息时间。
4. 运行中按 P 暂停后继续，三连障碍是否保持原有间距。
5. 加载 `dshclawd.game.v1` 的旧存档是否保持可玩。

`docs/preview-*.png` 已按 v0.8.1 重录（开始/在跑/滑铲/暂停/结算），由 Arcade 的浏览器 harness 真实渲染截图。

## v0.8.1 视觉层级约束

- 操作带为 y=118–180px，统一降低背景对比。真实障碍、Token、角色始终在其后绘制，保持高对比。
- 所有低障碍跨区域固定**黄橙色厚黑轮廓 + ! 警告牌**，所有高障碍固定**纯红激光 + 下箭头**，不能再以区域主题色改变交互提示。
- 所有可收集 Token 改成有深色外描边的金色像素金币，安全图案可用粉金中心；不再使用青色数据块与光晕。

## Token 双轨规则

**引导金币**：低障碍依靠当前 `speed`、`JUMP_V`、`GRAVITY` 绘制 8 枚抛物线金币；高障碍在激光门左右各绘制 3 枚贴地金币，门内完全留白。按引导首币位置操作，已模拟测试 170/218/290/360px/s 均能全收且不撞障。

**安全图案金币**：`heart` 心形、`diamond` 菱形、`arrow` 右向箭头、`paw` 爪印。每种图案使用原创 12px 点阵，仅允许出现在障碍组之间预留的空窗。空间不足直接跳过图案，不压缩、不与障碍混排。这种图形化糖豆思路参考《跑跑姜饼人》的关卡收集体验，但图案和美术均重新设计。

游戏不再有独立于障碍的随机 Token 刷新计时器。`tokenClearOfObstacle` 会按渲染轮廓增加额外 8px 净空，避免金币压到实际障碍和光束。金币类别与远处世界坐标保留在原有 `dshclawd.game.v1` 存档中。

## 完整原创像素资产

源文件 `assets/scene-atlas.svg`：192×144、12 格 48×48、可编辑；配套 `assets/scene-atlas.json` 清单。客户端使用同一 SVG 的离线内嵌副本，并通过 `drawMapExtraProps` 实际渲染。

| 区域 | 4 种独立道具 |
| --- | --- |
| 服务器区 | 终端控制台、网络机架、网络交换机、维护推车 |
| 冷却区 | 冷却阀门、冷却水泵、通风风扇、压力表 |
| 核心区 | 核心线圈、输电立柱、断路开关、应急控制板 |

原有气闸、冷却储液罐、核心密封舱仍保留为大型背景构件，所有像素道具均没有新增碰撞盒。
